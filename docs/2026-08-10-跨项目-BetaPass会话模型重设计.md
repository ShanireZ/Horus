## 零、一句话

**贝塔通取消了 SSO，会话判定从双超时改成三道门，撤权重投改成永不放弃。**

★★ **Horus 的两个客户端要分开做，通用心跳规格只适用于其中一个。**

| 客户端 | 形态 | 心跳规格 |
|---|---|---|
| **`horus-dashboard`**（监考看板） | 网页 | ✅ **照通用规格**：定时器 + `active` 计算 + `BroadcastChannel` 选主 |
| **`horus-client`**（采集端 Agent） | **原生桌面 exe** | ★★ **通用规格对它完全不适用** —— 它没有 `BroadcastChannel`、没有 `document.visibilityState`。**它自己定义 `active`** |

★ 这一条是对侧在碰撞审查里专门标出来的（其 X1）：
`docs/m4-identity-oidc.md` 写着 Agent = 学员机桌面程序、授权走**系统浏览器 + loopback 回调**。
**「全部 RP 实现心跳前端」这句话对 Agent 是错的。**

## 一、★★ `horus-client`（Agent）：自己定义 `active`

**Agent 本来就在采集机器上有无用户活动 —— 那个信号比浏览器的更准。**
它采集击键与事件流，「这台机器前面有没有人」是它天然就知道的事实，
不需要也不应该去模拟浏览器那套 `visibilityState` + `mousemove`。

**要做的：**

- 会话仍然照**三道门**判（见第二节的数值），但：
  - 「心跳」那道门：Agent 按**自己的节奏**上报存活（它本来就在持续上传事件流，
    ★ **可以复用那条通道，不必新开一个心跳端点**）。
  - `active`：用**采集到的机器用户活动**判定，不要用浏览器 API。
- ★ **`absolute` 那道门对 Agent 最要紧**：考试 2–3 小时，而 absolute 默认 6 小时。
  → **开考前预检**（对侧 P91）：**Horus 自己算自己的剩余时长**，
  不足以覆盖考试时长就先让学生重新登录。
  ★★ 原设计是靠 IdP 下发一个 claim 来告诉 RP「你的会话还剩多久」——
  **取消 SSO 后那条已作废**，改为 Horus 按自己的 absolute 自己算。
- ★ **不要照抄网页那套**：`BroadcastChannel` / `visibilityState` 在 exe 里根本不存在，
  照抄的结果是一段永远走不到的死代码，或者一个恒为 `false` 的 `active`
  —— 后者的表现是**每个学生考到 30 分钟就被 idle 踢掉**。

## 二、★★ 三道门取代双超时（P88–P92）

| 门 | 判据 | 新默认 | 挡什么 |
|---|---|---|---|
| **心跳** | 最后一次收到心跳的时刻 | **15 分钟**（5min × 3 次） | 关页面 / 关浏览器走人 |
| **idle** | 最后一次「人还在」的时刻 | **30 分钟** | **页面开着但人走了** |
| **absolute** | 建会话时写死的到期时刻 | **6 小时** | 前两道都被绕过时的最后一道；★ **任何活动都推不动它** |

- ★ **判定顺序**：revoked → absolute → idle → heartbeat。
- ★ **被动判定**：过期是「下一次请求进来时判」，**不要起定时任务或轮询**。
- ★★ **这三个值各平台完全自由调、不登记、贝塔通不拦**（P90）。
  原来那条「**RP 的 absolute 不得超过 IdP 的**」**已被正式取消**。
  → **Horus 的会话寿命本来就按「≥ 考试时长」配**（`oidcSessionMinutes`、
  `AdminSessionMinutes` 默认 180），**那条配置合法性不再有疑问**。
  ★ 但「自由调」不等于「随便填」：兜底改由「永不放弃的重投」承担，
  时长设长的代价从「撤权可能永远漏掉」降成了「撤权可能晚一点到」。

### 2.1 `horus-dashboard` 的心跳规格（照通用规格新写）

网页发，**5 分钟一次**，报文带一个 `active` 布尔：

- **任何**心跳 → 更新「心跳」那道门；**`active: true`** 的心跳 → **额外**更新 idle。
- `active` = 页面可见（`visibilityState === 'visible'`）**且**最近 5 分钟内有过
  `mousemove` / `keydown` / `click` / `scroll`。

**四条硬规格：**

1. **服务端节流 150 秒**，★★ **判据必须按字段分开** —— 若标签 A 的 `active:false` 先写入，
   标签 B 随后的 `active:true` 被整体节流掉，「人还在」这个信号就丢了。
   正确判据是「心跳够旧 **或**（本次是 active **且** idle 那个时间戳也够旧）」。
2. **前端 `BroadcastChannel` 选主**，只有 leader 发心跳；leader 广播超时 **15 秒**。
3. **心跳端点返回 204 无响应体**，不查用户表不查权限。
4. ★★ **心跳不是业务请求**；**反过来 —— 任何业务请求都不得续 idle。**
   ★★ **这一条对监考看板尤其致命**：看板是**持续自动轮询**的，
   把轮询算作活动的话 idle 那道门**永远不会到点** —— 监考机上开着看板就等于永不登出。
   **这正是对侧 P25 被翻案的直接原因。**

## 三、广播侧的变化（P85、P93、P94）

- **新增 reason `user_logout`**（用户选了「退出所有站点」）。
  ★ **Horus 零改造** —— 契约早已写死「不得按 `reason` 决定要不要清会话，
  **认不出的新值也要照清**」。★ **但要补一句给用户的提示语**。
  ★ 注意 Horus 有两套会话（`oidc_sessions` 与 `admin_sessions`）——
  收到 revoke 时**两套都要按 `sub` 清**，只清一套等于另一套里的人还在。
- **重投取消 `dead` 终态**（P93）：阶梯改为 **5min ×3 → 15min → 30min → 1h，共 6 次重投**，
  走完不放弃 —— 挂起等探活，探到你回来之后**从头再投一遍，直至成功**。
  → Horus 要能承受**同一条通知被重投很多次**，且**长时间下线再回来时会一次性收到一批积压的通知**。
  ★ `jti` 幂等台账正好覆盖这一点，**不要动它**；也**不要因为「这条太旧了」而丢弃**。
- ★★ **新增必办项：`GET /internal/health`**（P94），供贝塔通**每 5 分钟**探活。
  - 地址：与你登记的 `revoke_callback_url` **同源**的 `/internal/health`。
  - **必须验签**：与 `/internal/revoke` 同一套（拉 `/jwks`、按 `kid` 取公钥、`PS256`、
    `aud` 是不是自己）。不验就等于把「贝塔通接了哪些站」这份拓扑白送出去。
  - 任意 **2xx** 即算在线。**不要在这里查库或做重活**。
  - ★ **不要拿 `/internal/revoke` 当探活端点** —— 那会真的清会话。
  - ★★ **不实现它的后果**：贝塔通连续 3 次探不到即判 Horus 离线，**暂停对它的撤权重投**。
  - ⏳ **两个客户端各登记一个回调地址，因此探活也是两条** —— 两边都要实现，
    或者把没有服务端入口的那一个在贝塔通后台**关掉探活**（对侧 P95 提供了这个开关）。
    ★ 关掉探活同时意味着**停止对该平台的撤权重投**，所以这不是免费的，要想清楚再关。

### ★ 一条禁令

**收到 `/internal/revoke` 后只清本地会话，不得回调贝塔通的 `end_session`。**
`user_logout` 本身就是全域广播，回调过去就形成回环。

## 四、退出流程改成「范围二选一」（P85）

用户点 Horus 的退出 → 重定向到 `end_session_endpoint` → **贝塔通给他两个按钮**：

| 用户点了 | 贝塔通做什么 | Horus 要做什么 |
|---|---|---|
| **只退出本站** | 撤掉该 client 的 grant，重定向回 `post_logout_redirect_uri` | ★★ **在那个回跳里清掉自己的本地会话** —— 贝塔通不会替你清 |
| **退出所有站点** | 销毁全部授权，并向全部 RP 广播 `/internal/revoke`（`reason: user_logout`） | 照常处理那一发广播即可 |

★★ **「只退出本站」的回跳里必须清本地会话** —— 上游只撤 grant，
**你的本地会话它碰不到**。漏了的表现是「用户点了退出、跳回来了，然后发现自己还登录着」。
★ Horus 的 `/api/logout` 现在会销毁会话，**要确认它在「从贝塔通回跳」那条路上也被执行**，
而不是只在用户直接点本地退出时执行。

## 五、取消 SSO 对 Horus 的具体影响（P84）

- **每次授权请求都要求重新认证**。监考员进看板、学生启动采集端，
  **每次都要完整输一遍密码**（过 MFA 的还要再过一次）。
- ★★ **对 Agent 的 loopback 回调流程没有改变**，但**用时变长了** ——
  原来「系统浏览器里已有贝塔通会话 → 秒回 code」的路径**不存在了**。
  Agent 的启动引导文案与超时设置要按这个重新看一遍。
- ★ **无权限的人不再「秒回」**：没开 `horus-admin` 平台权限的人点进看板，
  **每点一次都要完整输一遍密码**才被拒（对侧 P98，明确不做缓解）。
  → ★ **无权限页不要再放「重新登录」按钮**，那等于请他再白输一遍密码。
  ★ 这条与 P83（Horus 拆成 `horus` / `horus-admin` 两个平台）叠加之后会更常见 ——
  学生误点看板入口就会撞上。**提示语要按 `rp-contract.md`「无权限时停在未登录」那节写。**
- ★★ **停服窗口内的 fail-closed 更硬了**：贝塔通不可用时**没有任何监考机能新登录管理端**
  （P83 已如实标注「无令牌后门」）。缓解仍然是**考前先登录 + 连通性预检**，
  ★ 而取消 SSO 之后「考前先登录」变得更重要 —— 因为再也没有「刚在别处登过所以能秒进」。

## 六、其他连带

- **session cookie 不持久**（P86）：网页侧登录后种的 cookie **不写 `Max-Age` / `Expires`**。
  ★ 它**不可靠**（浏览器的会话恢复会把它拿回来），只是零成本的加分项，
  **真正兜底的是心跳那道门**。
- **全员公用模式**（P87）：不做「记住我 / 常用设备」勾选，不做 IP 分档。
- **`AccessToken` TTL 3600 → 1800、`Grant` 604800 → 21600**（P96）。
- ★ **页面显著位置显示「当前登录：XXX + 一键退出」**（看板与 Agent 的界面都要）。
  机房电脑无还原卡、组策略与共享 PC 模式都不可行（对侧 R9），
  上一个人不点退出就走时，**让下一个人立刻看见这不是自己的号**是唯一稳定生效的缓解。
  ★ 对**考场**而言这一条尤其直接：学生轮流坐同一台机器正是常态。

## 七、要改的地方（清单）

| 位置 | 谁 | 改什么 |
|---|---|---|
| 会话时长配置（`oidcSessionMinutes` / `AdminSessionMinutes`） | 两个 | 按三道门重新表达：idle **30min**、absolute **6h**（可自行调，考试时长要覆盖得住） |
| 会话记录（`oidc_sessions` / `admin_sessions`） | 两个 | 新增「最后一次心跳时刻」字段，加第三道门 |
| 心跳上报 | `horus-dashboard` | 定时器 + `active` 计算 + `BroadcastChannel` 选主（leader 超时 15 秒） |
| 心跳上报 | **`horus-client`** | ★★ **自己定义 `active`**（用采集到的机器用户活动），**不要照抄浏览器那套** |
| 心跳端点 | 服务端 | 收 `{ active }`、**150 秒节流（判据按字段分开）**、返回 204；★ Agent 那侧可复用既有上行通道 |
| 新端点 `GET /internal/health` | 服务端 | **验签**、返回 2xx、不查库 |
| 轮询 | `horus-dashboard` | ★★ **看板的自动轮询不得续 idle** —— 这是本次最容易踩的一条 |
| 开考预检 | Horus | **自己算自己的 absolute 剩余**（原靠 IdP claim 的方案已作废） |
| 登出回跳 | 两个 | **确认回跳落地时真的清了本地会话** |
| revoke 处理 | 服务端 | `user_logout` 补提示语；★ **两套会话都要清** |
| 界面 | 两个 | 加「当前登录：XXX + 一键退出」 |
