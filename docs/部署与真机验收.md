# Horus 部署與真機驗收指南

> 面向**部署 / 監考維運**。本文是完整指南的唯一源；`docs/dist/部署与真机验收.md` 由 `scripts/generate-dist-docs.ps1` 生成，禁止手動維護第二份正文。成品目錄為 `dist/server`（監考伺服器）+ `dist/client`（採集 Agent）。
> 設計權威見 [architecture-v0.2.md](architecture-v0.2.md)、身分/RBAC/灰度 [m4-identity-oidc.md](m4-identity-oidc.md)、採集端硬化 [m5-agent-hardening.md](m5-agent-hardening.md)。

## 0. 架構與資料流（一句話）
- **監考伺服器**（一臺筆記本）：收採集資料 + 分析 + 寫入資料庫 + Web 看板。單場 30~60 人×2h **單機綽綽有餘**。
- **採集 Agent**（每臺考試機一個·需管理員）：採 OS 信號 + 截圖 → 區域網路上報伺服器。
- **資料全程區域網路內**；唯一可選出網 = 視覺 LLM 識圖（送派生圖·原圖永不出網）。判題走**外部洛谷**（不在本系統內）。
- 成品**自包含**（self-contained·免裝 .NET 執行環境），單檔案 exe。

## 1. 監考伺服器部署（`dist/server`）

### 1.1 前置
- 一臺 Windows 10/11 x64 筆記本；區域網路固定 IP（預設 `192.168.32.145`，Agent 內置指向此位址）。
- 無需安裝 .NET（自包含）。視覺/CLIP 的金鑰加密用 DPAPI（本機綁定），故**在部署機本機設定**。

### 1.2 設定 `server.config.json`（與 exe 同目錄）
關鍵項（完整註解見範本 / [../server/server.config.sample.json](../server/server.config.sample.json)）：

| 項 | 說明 |
|---|---|
| `urls` | 綁定位址。區域網路 `http://0.0.0.0:8080`；監考員遠端 OIDC 登入另需 https（見 1.5） |
| `pskBase64` | **採集鑑權共享金鑰**（authMode=psk/both）。32 位元組 base64，Agent 用**同一把** |
| `authMode` | `psk`（最簡·預設）\| `oidc`（貝塔通 per-user 身分）\| `both`（灰度共存）。見 §4 |
| `adminToken` | **管理端權杖**（adminAuthMode=token）。看板登入用。生產務必配（否則同網學員機可改設定/拉證據圖） |
| `adminAuthMode` | `token`（預設·靜態權杖）\| `oidc`（貝塔通帳號登入；存取資格由 `horus-admin` 平台開關判定·見 §4） |
| `keystrokeSecretBase64` | 擊鍵旁路 KSK（當前判題走外部洛谷·**無落點·可留空**） |
| `riskThreshold` | 入可疑佇列的風險閾值（預設 50） |
| `visionProvider`/`visionBaseUrl`/`visionModel`/`visionApiKey` | **視覺 LLM 識圖**（可選·唯一出網）。填明文 key，**啟動自動加密**為 `visionApiKeyEnc` 並清明文 |
| `embedProvider`/`embedOnnxModelPath` | **CLIP 按圖搜圖**（可選）。見 §6 |
| `retentionDays` | 留存天數（預設 30·到期關鍵資料轉 archive） |

### 1.3 生成金鑰（PowerShell）
```powershell
# 32 位元組 base64 PSK（採集共享金鑰；Agent 用同一值）
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
# 管理權杖（隨便一段高熵字串即可）
[Convert]::ToBase64String((1..24 | ForEach-Object { Get-Random -Maximum 256 }))
```
- **視覺/CLIP 的 API key**：直接把明文填進 `visionApiKey`，首次啟動會自動加密為 `visionApiKeyEnc` 並清空明文（DPAPI·本機綁定）。也可 `Horus.Server.exe protect-secret <明文>` 預生成密文。

### 1.4 啟動
```
Horus.Server.exe                 # 默认读同目录 server.config.json
Horus.Server.exe D:\path\server.config.json   # 或显式指定
```
- 啟動紀錄確認：`db=… 采集鉴权=开 管理鉴权=开`。
- 瀏覽器開 `http://192.168.32.145:8080` → 看板；輸入管理權杖（或走 OIDC 登入）。
- **非 loopback 綁定卻缺 PSK/管理權杖會拒絕啟動**（fail-closed）——生產必須配齊。

### 1.5 HTTPS（僅當監考員用貝塔通 OIDC 登入看板 / 遠端工作站時）
- `urls` 加 `https://0.0.0.0:8443`；`httpsSanHosts` 填伺服器 LAN IP/主機名。啟動**自動生成自簽證書**；監考機首用點過瀏覽器警告或預裝證書。

### 1.6 部署前一鍵預檢
- 看板頂欄「**預檢**」按鈕（或 `GET /api/preflight`）：檢查採集/管理端鑑權設定、貝塔通可達（OIDC 模式）、視覺 key、active 考試白名單覆蓋、both→oidc 遷移覆蓋。**全綠再開考**。

## 2. 採集 Agent 部署（`dist/client`·每臺考試機）

### 2.1 前置
- 每臺考試機 Windows 10/11 x64；**必須管理員權限**（ETW / UIAutomation / WMI / 抓屏）。
- 有預設瀏覽器（OIDC 模式登入用）。

### 2.2 設定 `agent.config.json`（與 exe 同目錄）
| 項 | 說明 |
|---|---|
| `agentId` / `machineId` | Agent 標識 / 機器標籤（每機唯一·跨考試固定） |
| `serverWsBase` / `serverHttpBase` | 伺服器位址 `ws://192.168.32.145:8080` / `http://192.168.32.145:8080`（Agent 內置預設即此，通常無需在設定裡寫） |
| `authMode` | `oidc`（推薦·填 `oidcIssuer`+`oidcClientId`·經瀏覽器登入貝塔通）\| `psk`（legacy·填下方 `psk`,**並須補配 `examId`/`seatId`**） |
| `oidcIssuer` / `oidcClientId` | oidc 模式：貝塔通 issuer `https://pass.betaoi.cc` + `horus-client`；cn 當前休眠；`oidcEndpointBase` 保留獨立設定，現場切換須審閱 |
| `oidcScope` | 固定 `openid profile`；不要登記或請求舊的 `horus_profile` |
| `psk` / `examId` / `seatId` | 僅 psk(legacy) 模式：伺服器 `pskBase64` 同一把 + 手動指定考試/座位 |
| `whitelistHosts` / `whitelistProcs` | 允許的判題站 / 處理程序（IDE/編譯器等）——也可由伺服器下發覆蓋 |
| `targetHeight` / `webpQuality` / `baselineMinSeconds` / `baselineMaxSeconds` | 截圖解析度/品質/隨機基線區間 |

> **考試派發(2026-07-03)**:oidc 模式**不設定 examId/seatId** —— examId 由伺服器端派發(「當前活躍考試」= 看板/`POST /api/exams` 建的最近一場 active),seatId 由貝塔通 userinfo 的 `username` 派生（缺失或不安全時退回 `sub`）。學員/維運零考務設定,每臺機設定一次、場場通用。

### 2.3 啟動
- **雙擊 `Horus.Agent.exe` 即可**（exe 內嵌 `requireAdministrator` manifest,自動彈 UAC 提權;無需右鍵「以管理員身分執行」。預設讀同目錄 `agent.config.json`）。
- `oidc` 模式(推薦):啟動後**待命**(不採集),輪詢伺服器;監考端建好考試(active)後,自動彈系統瀏覽器登入貝塔通 → 授權 → 開始採集。**考試結束(`end`)或被全場登出(`logout`)後自動停採回待命**,等下一場。
- `psk` 模式(legacy):按設定的 examId/seatId 直接連伺服器,單場執行。
- 看板對應座位變**線上**(oidc 下座位名 = 貝塔通 userinfo 的 `username`，必要時退回 `sub`)。

### 2.4 保活 / 抗規避（M5·推薦·見 §5 驗收）
三層縱深，任一層的備援都是「關掉即心跳斷 → 看板告警 → 物理監考介入」：
- **層2 兄弟看門狗**（無需裝服務）：`Horus.Agent.exe --watchdog`（拉起並監控採集處理程序·被殺秒級重新啟動）。
- **層1 Windows 服務（最強·標準帳戶殺不掉 LocalSystem 服務）**：
  ```
  Horus.Agent.exe install-service      # 管理员运行:注册 LocalSystem 服务·自动启动·拉起采集进用户会话
  Horus.Agent.exe uninstall-service    # 卸载
  ```
- **層3 心跳告警**：已內建，採集被關/掛起 → 看板座位離線/健康告警。

## 3. 開考標準流程
1. **伺服器**建考試 + 下發白名單（看板 / `POST /api/exams/{id}/config`）。
2. 各考試機起 Agent（或 M5 服務已自啟）。
3. **考前預檢**（看板「預檢」按鈕）→ 全綠。
4. 開考：看板即時座位熱力 + 可疑佇列。**系統只初篩，處分由人裁決**。
5. 考後：看板結束考試（`status=ended`）。到期自動歸檔。

## 4. M4 身分層（OIDC / RBAC·可選進階）
- **採集面 OIDC**（psk→oidc）：per-user 身分取代共享 PSK，閉合跨身分栽贓/seq 搶佔。灰度驗收清單見 [m4-identity-oidc.md §11](m4-identity-oidc.md)（★ §11 的 runbook 仍有效，但**前置條件那一段已過期**：IdP 是貝塔通、端點在根路徑、scope 是 `openid profile`，見該文件首段訂正表）。
- **線級合同**：issuer 固定 `https://pass.betaoi.cc`；簽名只接受 **PS256**；端點是根路徑 `/auth`、`/token`、`/jwks`、`/me`、`/session/end`；身分欄位 `sub` / `name` / `username` 從 userinfo `/me` 取得，id_token 只作為 subject 與協定錨點。
- **管理端存取資格**（token→oidc）：誰能進監考看板由貝塔通的 `horus-admin` 平台開關回答，Horus 本機不判角色。監考員用貝塔通帳號登入看板（需 §1.5 HTTPS + 貝塔通側 `horus-dashboard` client；採集端 `horus-client` 歸屬平台 `horus`）。
- **兩條軸獨立**，可各自灰度。切 oidc 前用預檢 `migration` 項確認線上座位全部遷移。

## 5. M5 採集端硬化·真機驗收清單
（在真機逐條驗，純檢測取證·不阻斷作弊，只讓規避暴露）
1. **服務保活**：`install-service` → start → 採集在**使用者工作階段**起、能截屏（看板有該座位截圖）。
2. **殺採集**：任務管理器結束 `Horus.Agent.exe` → 看門狗**秒級重拉**（看板短暫離線後恢復）。
3. **殺看門狗**：結束看門狗處理程序 → 採集端**重拉一個 adopt 看門狗**（層2 互拉）。
4. **標準帳戶**：以學員標準帳戶嘗試停服務 → **停不掉**（LocalSystem）。
5. **防掛起**：休眠/睡眠後恢復 → 看板出現 `suspected_suspend` 健康告警。
6. **防遮蔽**：用純色視窗蓋住主屏 → `screenshot_obscured` 入可疑佇列。
7. **防降權限**：非管理員啟動 Agent → `capability_degraded` 告警（看板座位健康標）。

## 6. CLIP 按圖搜圖（可選）
「按已知作弊圖撈全場相似影格」。規模小 → C# 暴力餘弦，無需 sqlite-vec。僅嵌**證據圖**（省算力）。

**嵌入源 = 本機 ONNX CLIP**（★實測小米 MiMo-V2.5 **無** `/v1/embeddings` 端點 → 重複使用視覺 key 走不通；本機 ONNX 零出網·CPU·無需 GPU）。

### 6.1 下載模型（只下**一個 .onnx 檔案**）
★ **不需要**單獨的「解碼器/預處理器」——圖像預處理(縮放 224 + CLIP 歸一化)已內置在 Horus，圖片解碼用內置 ImageSharp。HF 倉裡的 `config.json`/`preprocessor_config.json` 都不用下。

★ **約定檔案名 = `model.onnx`**(與推薦倉的原始檔案名一致,下載後**免改名**;`embedOnnxModelPath` 留空即預設找 `dataDir\model.onnx`)。

| 來源 | 檔案 | 直接下載連結 |
|---|---|---|
| **① 推薦** Qdrant/clip-ViT-B-32-vision(專為圖像 embedding·MIT·352MB) | `model.onnx`(原名即約定名) | `https://huggingface.co/Qdrant/clip-ViT-B-32-vision/resolve/main/model.onnx` |
| ② 小體積 Xenova/clip-vit-base-patch32(fp32·約幾十 MB) | `vision_model.onnx` → **改名 `model.onnx`** | `https://huggingface.co/Xenova/clip-vit-base-patch32/resolve/main/onnx/vision_model.onnx` |
| ② 更小(int8 量化) | `vision_model_quantized.onnx` → **改名 `model.onnx`** | `https://huggingface.co/Xenova/clip-vit-base-patch32/resolve/main/onnx/vision_model_quantized.onnx` |

PowerShell 一行下（放進伺服器 `data\` 目錄,保持約定名）：
```powershell
Invoke-WebRequest "https://huggingface.co/Qdrant/clip-ViT-B-32-vision/resolve/main/model.onnx" -OutFile "data\model.onnx"
```

### 6.2 設定（server.config.json）
```json
"embedProvider": "onnx",
"embedOnnxModelPath": "",
"embedOnnxInput": "",
"embedOnnxOutput": "",
"embedDim": 512,
"embedBackstopMinutes": 5
```
- `embedOnnxModelPath`：**留空 = 約定名 `model.onnx`**(即 `dataDir\model.onnx`,預設 `data\model.onnx`);放別處才顯式填——相對路徑按 `dataDir` 解析,也可絕對路徑。
- `embedOnnxInput` / `embedOnnxOutput`：**留空即可**——Horus 自動選(輸入取模型首個;輸出優先挑名字含 `embed`/`pool` 的、正確取到嵌入向量)。特殊模型可用 Netron(netron.app)打開 .onnx 看輸出名再填。
- `embedBaseUrl` / `embedModel` / `embedApiKey`：**留空**（這三個是給雲端 `openai` provider 的，本機 onnx 用不到）。
- `embedDim`(512·僅記錄·暴力餘弦不挑維度) / `embedBackstopMinutes`(後台補嵌間隔)：預設即可。

### 6.3 驗證
1. 啟動紀錄出現 **「ONNX CLIP 嵌入器就緒 model=… out=…」** → 載入成功(`out=` 顯示自動選中的輸出名)。
2. 看板打開證據圖 → 燈箱點「**按圖搜圖**」→ 撈出相似影格(後台每 5 分鐘自動嵌證據圖·或搜索時即時補嵌)。

> 雲端點(若某供應商確有圖像 embedding 模型)才用 `embedProvider=openai`;部署前可 `Horus.Server.exe probe-embed [model]` 探測其有無 `/v1/embeddings` 圖像模型。

## 7. 常見故障排查
| 現象 | 原因 | 處置 |
|---|---|---|
| 伺服器拒絕啟動「未設定採集面鑑權/AdminToken」 | 非 loopback 綁定缺 PSK/權杖（fail-closed） | 配 `pskBase64` + `adminToken`；僅整合測試可 `allowInsecure:true` |
| 座位一直離線 | Agent 未起/網路不通/身分不符 | 起 Agent；核對 serverWsBase/防火牆；psk(legacy) 模式再核對 examId/seatId 與伺服器一致 |
| Agent 一直待命不彈登入 | 伺服器沒有 active 考試 / HTTP 位址不可達 | 看板建考試（active）；核對 `serverHttpBase`；Agent 紀錄有「暫無活躍考試」即連線路徑通 |
| OIDC 登入報 `no_active_exam` | 登入瞬間考試被結束 / 尚未建考試 | 建考試後 Agent 會自動重試 |
| Agent 報 `capability_degraded admin` | UAC 被點了「否」/ 手動繞過了 manifest | 重開 exe 並允許 UAC / 走 M5 服務 |
| 監考員看板 OIDC 登入失敗 | 貝塔通不可達 / `horus-dashboard` client 或 `horus-admin` 平台權限未配 / 回呼非 https | 預檢 `issuer_reachable`；核對貝塔通用戶端與平台授權；伺服器起 https |
| `kid 未命中 JWKS` / 演算法不匹配 | 貝塔通 PS256 金鑰輪換 / 誤把舊 RS256 加入允許清單 | 從 `/jwks` 同步新 key；允許演算法保持僅 PS256；重新啟動 |
| 按圖搜圖無結果 | 未配嵌入器 / 模型缺失 / 尚無證據圖 | 配 `embedProvider=onnx`+模型；等有證據圖被嵌入 |
| 視覺分析不出結果 | key 未解出 / 端點不通 | 預檢 `vision` 項；查 baseUrl/model/key |

> 安全鐵律：真實設定（PSK / 權杖 / API key）在 `*.config.json`（**已 gitignore·切勿提交/外發**）；散布只發 `*.sample.json` 範本。
